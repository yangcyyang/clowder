# FDE 职业道德六底线

## R — 原文 (Reading)

> "我认为 FDE 的职业道德至少有六条底线，写出来与所有同行共勉。第一，数据的主权属于客户。在客户现场看到的数据，一个字节都不应该出现在不该出现的地方——不进入人工智能的训练数据（除非合同明确授权），不进入案例素材（除非客户书面同意），不进入你下一份工作的谈资。……第五，对『客户要求但不该做的事』说不。……『法国侍者』的隐喻在这里有最深的含义——真正的专业，不是满足客户的一切要求，而是敢于引导客户走向对他真正有利、也对世界无害的方向。"
>
> — 范冰《前线部署工程师》后记

---

## I — 方法论骨架 (Interpretation)

FDE 握着客户组织最深处的秘密和越来越大的代替人做决定的权力。六条底线：

1. **数据主权属于客户**——客户现场看到的数据一个字节都不该出现在不该出现的地方；数据访问最小化原则（能不看的就不看，能脱敏的就脱敏）
2. **诚实报告结果，包括坏消息**——按结果收费模式里最大的道德风险是粉饰结果（把"上线了"包装成"价值实现了"，把相关性包装成因果）；价值度量系统可以是最诚实的工具，也可以是最精巧的谎言机器
3. **不制造依赖，不贩卖恐惧**——两种隐蔽的恶：故意做黑箱让客户离不开你；夸大"不用 AI 就会死"的恐慌促交易；健康模式"做完会走"（知识转移+能力沉淀）
4. **把"被替代的人"当回事**——不要在被替代者面前庆祝效率，不要把人在方案里写成"成本项"而不给出路；"技术是中立的"是借口——部署者每天做的选择本身就是立场
5. **对"客户要求但不该做的事"说不**——会遇到的灰色要求："把员工行为监控做得再细一点""数据合规模糊但先接了再说"；"法国侍者"隐喻——真正的专业不是满足一切要求，是敢于引导客户走向对他有利也对世界无害的方向；说不的底气来自账上有别的客户——道德从来也和商业模式有关
6. **记住你代表"技术"本身**——对很多客户，你是他们接触 AI 的第一副面孔；每一次夸大都在透支行业信用，每一次兑现都在为行业存款

核心逻辑：这份信任是 FDE 模式的地基，而毁掉它，只需要一次越界。

## A1 — 书中的应用 (Past Application)

### 案例1: Palantir 的权限与审计纪律
- **问题**: 服务敏感客户怎么自处？
- **方法论的使用**: 把"权限与审计"做到产品内核（谁看过什么数据全程可查），最小知情纪律
- **结论**: 正因为它服务领域敏感，它的工程师文化里那些关于权限/审计/最小知情的纪律才格外值得借鉴
- **结果**: 能在情报界生存二十年

### 案例2: 高德纳 70% 预测 = 全行业警钟
- **问题**: 为什么"被绑定"的客户会集体反抗？
- **方法论的使用**: 2028 年 70% 企业将因成本与技能空心化放弃 FDE 主导方案
- **结论**: 不制造依赖是道德，也是商业模式长期存续的必然
- **结果**: 成为职业道德第三底线的注脚

### 案例3: "法国侍者"的反面
- **问题**: FDE 是不是客户要什么给什么？
- **方法论的使用**: 卡普反对唯唯诺诺的接单式工程文化
- **结论**: 真正的专业是敢于说不、引导客户
- **结果**: 成为职业道德第五底线的理论源头

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 客户提出灰色地带要求（数据/监控/夸大）
2. 需要判断某个要求该不该做
3. 交付涉及替代人工，需要伦理反思
4. 被要求粉饰结果或隐瞒坏消息

### 语言信号

- "客户要我们做员工行为监控，合法吗？"
- "客户的数据能拿来训练模型吗？"
- "客户要求我们把结果说得好听点"
- "这个需求感觉不太对，但客户坚持"

- 与 `psf-screening`：PSF 判断问题值不值得做，伦理判断该不该做

## E — 可执行步骤 (Execution)

1. **六底线逐条对照**
   - 完成标准：把当前要求过六条——数据主权/诚实报告/不制造依赖/善待被替代者/不该做的事说不/代表技术本身
   - 判停条件：任意一条被触犯且无缓解方案 → 启动步骤 2

2. **找合规依据而非拍脑袋**
   - 完成标准：确认合同条款（数据授权范围）/ 书面同意（案例素材）/ 合规边界（行为监控合法性）
   - 判停条件：合同没写、客户不书面确认 → 按"不授权=不能做"处理

3. **设计体面的"说不"方案**
   - 完成标准：把拒绝翻译成替代方案或引导（"这个数据合规上有风险，但我们可以先接合规的子集"）；明确说不的底气来自业务多元（账上有别的客户）
   - 判停条件：没有替代方案 → 直接拒绝并说明理由
   - 参考："法国侍者"反面——满足一切要求不是专业

4. **诚实报告的纪律自查**
   - 完成标准：检查任何对外表述——"上线了"≠"价值实现了"？相关性包装成因果了吗？坏消息会被隐瞒吗？
   - 判停条件：有粉饰动机 → 回到"敢被检验"的立身之本

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 日常技术决策（无伦理张力）
- 明确违法行为（直接拒绝并记录，不需道德讨论）

### 书中警告的失败模式

- 数据越界：一个字节出现在不该出现的地方，毁掉整段信任
- 粉饰结果：价值度量系统变成谎言机器
- 制造依赖/贩卖恐惧：高德纳预测是给全行业的警钟
- 把被替代者当成本项：不给路的方案会在续约时遭遇最坚定反对者
- 用"技术中立"当借口：部署者每天的选择本身就是立场

### 作者的盲点 / 时代局限

- 六底线是"应然"规范，缺乏执行机制设计（书中未给"违约怎么办"）；团队落地需自建监督（如伦理审查会）
- "不制造依赖"与商业利益（绑定）存在张力，实践中需要长期主义的组织文化支撑

### 容易混淆的邻近方法论

- 不是"合规审查"——合规是外部最低标准，伦理是内部更高要求
- 不是"风险规避"——有些事不违法但有伦理问题，判断标准是"对客户有利且对世界无害"
