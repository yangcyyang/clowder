# Parallel Merge

用于多猫并行讨论后的 Reduce 阶段。目标是让铲屎官只看合流卡就能裁分歧，
不必通读每只猫的全文。

## 触发场景

- 并行轮结束后，你被指定为合流猫。
- 用户说“合流一下”“汇总一下大家的观点”“收敛一下分歧”。
- 并行模式产出不少于 2 份实质回答，且需要给出可裁决摘要。

## 输出格式

必须固定输出三段：

### ① 共识

合并各猫一致的结论。只写确实被多方支持的内容，不把单方观点伪装成共识。

### ② 分歧点

逐条列出分歧：

```markdown
- 分歧：[问题]
  - [猫 A] 主张：[观点]；理由：[原消息中的理由]
  - [猫 B] 主张：[观点]；理由：[原消息中的理由]
```

分歧必须能溯源到原消息；没有分歧就写“无实质分歧”。

### ③ 建议裁决

给出合流猫的倾向和一句理由，并标注：

```markdown
仅供参考，最终裁决归铲屎官。
```

## 纪律

- 不新增观点：合流卡只能压缩和组织已有回答。
- 不偏袒发起者：按证据和理由强度合流，不按谁先说或谁派工。
- 不和稀泥：真实分歧要保留，不能用模糊表述抹平。
- 不写长文：全文控制在铲屎官 2 分钟内可读完。
- 缺原消息时先说明缺口，再请求补充，不凭印象编分歧。
