# 倒金字塔提案撰写

## R — 原文 (Reading)

> "多数技术团队写的提案都在犯同一个错误：通篇讲『我们要做什么』，而不是『你将得到什么』。好的 FDE 提案，遵循一个严格的倒金字塔结构。第一层：业务结果，一段话说完。提案的第一段，必须是客户语言的业务结果：『八周内，把你行反洗钱调查的平均处理时间从 4 小时降到 15 分钟，释放的调查产能相当于现有团队的 2.5 倍。』没有这一句，客户的高管根本看不进去后面的内容。"
>
> — 范冰《前线部署工程师》3.10

---

## I — 方法论骨架 (Interpretation)

倒金字塔提案是企业市场单价最高的文本。结构四层，从上到下信息密度递减、信任信号递增：

1. **第一层：业务结果，一段话说完**——客户语言的业务结果（数字+动词+时限），没有这句高管看不进后面的内容
2. **第二层：价值验证路径**——验收指标/测量方法/基线数据/每阶段退出机制；传递的信号是"我们敢被检验"（在被过度承诺伤害过的企业市场里，敢被检验是最稀缺的诚意）
3. **第三层：交付方法**——才轮到技术方案，且让非技术读者跟上（架构图配业务注释，里程碑配决策点）；写明客户该配合什么（数据访问/关键人员投入）——提前排雷+筛选客户
4. **第四层：风险与对策**——"把死法说清楚"的供应商最受成熟买家信任（数据质量不达标/关键人员变动/准确率达不到门槛）；是信任放大器

关键：概念验证方案的"毕业标准"就写在这里（周期上限/验收指标/毕业与散伙两种后续）——写得含糊的验证方案，等于给概念验证坟墓签发开工许可。

核心逻辑：提案不是技术说明书，是"信任的工程"——每一层都在降低客户的风险感知。

## A1 — 书中的应用 (Past Application)

### 案例1: 反洗钱提案（书中示范）
- **问题**: 怎么写提案让高管看得进去？
- **方法论的使用**: 第一段直接给业务结果——"八周内，把反洗钱调查平均处理时间从 4 小时降到 15 分钟，释放产能相当于现有团队 2.5 倍"
- **结论**: 先结果后方法
- **结果**: 成为书中反复引用的倒金字塔示范

### 案例2: 概念验证方案的特殊性
- **问题**: POC 方案怎么写才不烂尾？
- **方法论的使用**: 把毕业标准写进方案（周期上限/验收指标/毕业与散伙两种后续）
- **结论**: 写得含糊=给概念验证坟墓签发开工许可
- **结果**: 与 poc-rejection 机制互为表里

3. 需要把技术方案转译成客户能理解的语言

## E — 可执行步骤 (Execution)

1. **写第一层：业务结果**
   - 完成标准：一段话 = 时限 + 客户语言的数字结果 + 对比反差（"从 X 到 Y"）
   - 判停条件：第一段还在讲技术方案 → 重写
   - 参考句式："[时限]内，把[客户指标]从[A]降到[B]，[释放/节省]相当于[对比物]"

2. **写第二层：价值验证路径**
   - 完成标准：验收指标 + 测量方法 + 基线数据 + 每阶段退出机制
   - 判停条件：没有基线数据 → 补（基线只在项目启动那一刻存在）
   - 备注：这一层传递"我们敢被检验"

3. **写第三层：交付方法**
   - 完成标准：架构图配业务注释 + 里程碑配决策点 + 客户配合事项清单（数据访问/关键人员投入）
   - 判停条件：非技术读者读不懂 → 重写
   - 备注：把客户该干什么写清楚=提前排雷+筛选客户

4. **写第四层：风险与对策**
   - 完成标准：列出 3+ 个"我们想过会怎么死"（数据质量/人员变动/准确率门槛）+ 对策
   - 判停条件：通篇没有风险段落 → 加；回避风险=失去信任
   - 备注：成熟买家最信任"把死法说清楚"的供应商

5. **POC 方案附加：毕业标准块**
   - 完成标准：写明周期上限 + 验收指标 + 毕业与散伙两种后续
   - 判停条件：方案里没有"结束"的定义 → 等于签发坟墓开工许可

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 内部技术设计文档（读者是工程师，不需要倒金字塔）
- 产品白皮书/品牌内容（用途是教育市场，不是单客户成交）

### 书中警告的失败模式

- 通篇讲"我们要做什么"不讲"你将得到什么"
- 第一层写技术方案：高管看不进去
- 回避风险：仿佛提了就不吉利——恰恰相反
- POC 方案无毕业标准：给坟墓签发开工许可

### 作者的盲点 / 时代局限

- "客户语言"在跨文化场景（出海）需要双语言表达，倒金字塔结构需适配
- 2026 年提案被 AI 辅助生成的普遍化，让"具体数字+真实基线"的差异化价值上升（模板化提案不再有说服力）

### 容易混淆的邻近方法论

- 不是"销售话术"——提案是书面信任工程，话术是口头临场
- 不是"技术规格书"——那是第三层的子集
