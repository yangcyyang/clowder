# 拒绝机制与免费验证治理

## R — 原文 (Reading)

> "拒绝错误的项目，是 FDE 模式最重要的盈利能力。……FDE 团队需要一套『拒绝的机制』，而不只是拒绝的勇气。三条可操作的防线。防线一：概念验证必须有『毕业标准』。每个验证项目启动时就写明：多少周后、用什么指标、达到什么数值，项目『毕业』进入付费部署；达不到，双方体面散伙。"
>
> — 范冰《前线部署工程师》2.3

---

## I — 方法论骨架 (Interpretation)

这个 skill 处理"验证项目的进出治理"：FDE 成本结构前置（最好的工程师/最贵的差旅/最长的现场投入都在回款前），接错一个项目不是亏一单，是整支精英团队被拖住、机会成本雪崩。

核心逻辑：
1. **拒绝是盈利能力**——错误的试点烧掉的不只是成本，还有团队时间、士气、产品复利
2. **要机制不要勇气**——勇气靠个人，机制靠流程
3. **毕业标准先于开工**——周期上限、验收指标、毕业/散伙两种后续，开工前白纸黑字
4. **免费是手段，收费是目的，转换设计是生死**——概念验证坟墓多数不是因为技术失败，而是没有设计"结束"的机制

三防线 + 五开关：
- **防线一**：毕业标准（多少周/什么指标/什么数值→毕业或散伙）
- **防线二**：警惕三类高危信号（无主之地/只许看不给碰/宇宙级需求，出现两个以上高度警惕）
- **防线三**：给拒绝留个体面的台阶（把"现在不做"翻译成"什么时候做"）
- **转换五开关**：毕业标准先于开工 / 免费边界显性化 / 内部支持者变销售员 / 价格锚点提前埋设 / 给"不转正"设计体面出口

## A1 — 书中的应用 (Past Application)

### 案例1: 中国服务商官网劝退文案
- **问题**: 怎么拒绝错时机启动的客户？
- **方法论的使用**: 官网公开写"场景没验证的去参加演示""数据一张表就能导出的用轻量服务"
- **结论**: "FDE 是重投入，我们宁可你晚一点开始，也不希望你在错的时机开始"
- **结果**: 把拒绝包装成对客户负责，反而建立信任

### 案例2: Palantir 烧试点当研发组合
- **问题**: 免费试点亏钱怎么办？
- **方法论的使用**: 把试点当研发组合投资——像风投一样，多数下注归零没关系，成的赢回一切
- **结论**: 前提是"把失败试点转化为产品资产"的机制
- **结果**: 训练营把验证转化率从早期 5-10% 提升到约 75%

### 案例3: 概念验证坟墓（日本公司）
- **问题**: 项目拖着没有结果
- **方法论的使用**: 无毕业标准的反面教材——"无限期、无指标、无裁判"
- **结论**: 半年后从汇报材料悄悄消失，自然死亡
- **结果**: 证明"写得含糊的验证方案，等于给概念验证坟墓签发开工许可"

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 客户提出做 POC/试点/免费验证，需要判断接不接
2. 手头有项目"持续推进中"快一年了，需要决定砍还是救
3. 设计免费验证方案的边界（免费到哪天/覆盖什么/超出怎么计价）
4. 验证成功后要转付费，需要设计转换机制

### 语言信号

- "客户想先做个 POC"
- "这个试点项目拖了大半年了"
- "免费验证要不要做？"
- "怎么让验证项目顺利转成付费？"

### 与相邻 skill 的区分

- 与 `psf-screening`：PSF 判断"问题值不值得做"，拒绝机制判断"项目该不该接、怎么接才不烂尾"
- 与 `mvd-validation`：MVD 是怎么做验证（军规），拒绝机制是验证的进出治理（毕业标准）

## E — 可执行步骤 (Execution)

1. **接单前排查三类高危信号**
   - 完成标准：检查——有明确的业务方负责人吗？客户肯给真实数据吗？需求是不是"宇宙级"？
   - 判停条件：三类信号出现两个以上 → 启动拒绝流程（走步骤 4）
   - 备注：无主之地（只有信息部门对接）是最高频的死亡信号

2. **设计毕业标准（开工前必做）**
   - 完成标准：写出"多少周后 + 什么指标 + 达到什么数值 = 毕业进入付费部署；达不到 = 体面散伙"
   - 判停条件：写不出验收指标 → 项目还没想清楚，别开工
   - 参考：验证周期以"周"计不以"月"计

3. **显性化免费边界与价格锚点**
   - 完成标准：明确免费到哪一天/覆盖什么/超出怎么计价；免费期开始谈价值数字（"这个月为你们释放约 120 个人时"）
   - 判停条件：免费边界模糊 → 收费日客户会感觉"被宰了一刀"

4. **设计转换与退出双路径**
   - 完成标准：写清"验证通过怎么转付费（内部支持者当销售员）"和"不转正怎么体面退出（暂停但保留/约定重启/维持联系）"
   - 判停条件：没有退出路径 → 项目会烂在坟墓里

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 问题已通过 PSF 三关、正式合同已签的交付项目（该用激活/续约类 skill）
- 纯内部研发项目的立项（没有"客户现场"语境）

### 书中警告的失败模式

- 只有拒绝的勇气没有机制：靠个人魄力，人走机制就崩
- 免费变"无限居留制"：模糊边界培养"免费是常态"预期
- 强扭的转化是毒药合同：不达标的客户硬转正，后面全是坑
- 忽视"失败也要让失败值钱"：失败的验证没回流为行业理解/组件/评估数据

### 作者的盲点 / 时代局限

- "宁可晚开始"的立场在竞争激烈的 2026 年 AI 市场可能被竞争对手抢单
- 毕业标准在客户强势（如国央企）场景可能被压成形式

### 容易混淆的邻近方法论

- 不是"不接单"——是"错时机不接"，对的时机要接
- 不是"风投式乱烧"——Palantir 烧试点的前提是回流机制，没有机制就是纯失血
