# 进场尽调：五份地图

## R — 原文 (Reading)

> "FDE 进场前后，有一个动作叫『进场尽调』：在写第一行代码之前，用结构化的方法，摸清这个客户的全部家底。一份完整的尽调清单，包含五份地图。……两周尽调省下的，是三个月在错误战场上的狂奔。"
>
> — 范冰《前线部署工程师》3.4

---

## I — 方法论骨架 (Interpretation)

进场尽调是在写第一行代码之前，用结构化方法摸清客户全部家底。五份地图缺一不可：

1. **数据地图**：客户有哪些数据源、谁拥有、质量如何、权限归谁——重点不是"有什么"，是"哪个被信任"（官方数据源和被员工信任的数据源往往不是同一个）
2. **流程地图**：目标业务流程的真实运转图（影子工作法观察出来的版本）——特别标注三个点位：时间消耗最大、出错代价最大、情绪最激烈（这三个点位通常是价值富矿）
3. **组织地图**：谁发起、谁买单、谁使用、谁能否决、谁是无冕之王——特别找"知识枢纽"（职位不高但所有人遇到实际问题都找他）
4. **系统地图**：技术环境真实面貌——对接系统清单及接口状态、安全合规边界、变更管理流程（"客户发布一个版本要走六周流程"这种信息决定排期）
5. **政治地图**：最敏感也最关键——这个项目动了谁的奶酪？自动化的目标流程是不是某个部门的权力来源？提前识别恐惧的载体（怕被取代、怕被证明无能），并在方案里安排"新生路"而非"死路"

核心逻辑：企业项目最常见的死因不是技术，是没算准组织账（支持者职位不够高/太高/正确的人没被纳入）。

## A1 — 书中的应用 (Past Application)

### 案例1: 数据地图的"信任"要点
- **问题**: 官方数据源可靠吗？
- **方法论的使用**: 几乎每个组织里，官方数据源和被员工真正信任的数据源都不是同一个——后者才是你要接的
- **结论**: 尽调数据地图时要问"哪份被信任"而非"有什么"
- **结果**: 避免接错数据源导致"垃圾进垃圾出"

### 案例2: 系统地图的排期炸弹
- **问题**: 为什么很多项目时间表第一天就破产？
- **方法论的使用**: 没人问清楚"客户那边发布一个版本要走六周流程"
- **结论**: 系统地图决定部署架构和排期
- **结果**: 尽调时画出系统地图、把集成风险分级排期，最硬的骨头最早啃

### 案例3: 政治地图的"新生路"
- **问题**: 员工抵触新工具怎么办？
- **方法论的使用**: 抵触的根源大多不是懒，是恐惧；提前识别恐惧载体，在方案设计里给"受损者"安排新生路
- **结论**: "被你设计成受害者的人，会成为续约时最坚定的反对者"
- **结果**: 政治地图成为变革管理的前置准备

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 拿到新客户，进场前需要系统摸底
2. 项目推进卡住，怀疑是对客户了解不足
3. 需要判断客户组织的权力结构和项目死因风险
4. 制定进场第一到两周的工作计划

### 语言信号

- "新客户进场前要准备什么？"
- "怎么快速摸清客户的真实情况？"
- "这个项目总是卡壳，是不是没摸清客户家底？"
- "进场第一周该干哪些事？"

### 与相邻 skill 的区分

- 与 `shadow-work`：影子工作法是尽调中流程地图/组织地图的"观察方法"；五地图是尽调的"产出框架"
- 与 `psf-screening`：PSF 判断问题值不值得，尽调为交付排期/架构/变革管理做准备

## E — 可执行步骤 (Execution)

1. **画数据地图**
   - 完成标准：列出数据源清单 + 每项的"谁拥有/质量/权限/是否被信任"
   - 判停条件：只写了"有什么"没写"哪个被信任" → 重画
   - 输出：确认"要接的数据源"是员工真正信任的那个

2. **画流程地图（配合影子工作法）**
   - 完成标准：画出真实运转流程（含变通），标注三个点位（时间消耗最大/出错代价最大/情绪最激烈）
   - 判停条件：画的是流程文件版本而非观察版本 → 重做

3. **画组织地图**
   - 完成标准：标出"发起/买单/使用/否决/无冕之王"五角色 + 知识枢纽
   - 判停条件：找不到知识枢纽 → 还没进到组织深处
   - 备注：评估支持者职位是否"刚好够高"（太高没时间管你，太低没权力）

4. **画系统地图**
   - 完成标准：对接系统清单 + 接口状态 + 安全合规边界 + 变更管理周期
   - 判停条件：不知道客户发版要走几周流程 → 排期会破产
   - 输出：集成风险分级，最硬的骨头排最早

5. **画政治地图（最敏感）**
   - 完成标准：回答"自动化动了谁的奶酪？" + 每个受损角色的"新生路"预案
   - 判停条件：没有识别任何受损者 → 还没深入政治现实
   - 输出：把"新生路"写进方案设计（不是事后补救）

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 老客户常规迭代（家底已知，不需要每次全量尽调）
- 纯远程轻量项目（五地图中的政治/流程地图依赖现场观察）

### 书中警告的失败模式

- 尽调当纯成本：账要这么算——两周尽调省下三个月在错误战场上的狂奔
- 只做前四图不做政治图：跳过最敏感也最关键的一份
- 组织账没算准：支持者职位不够高/太高/正确的人没被纳入

### 作者的盲点 / 时代局限

- 五地图方法论源自 Palantir 的情报/国防文化（政治地图的敏感性），在普通商业客户场景可能不适用或需弱化
- 尽调耗时 1-2 周，2026 年 AI 工具（自动化集成）开始压缩系统地图的工作量

### 容易混淆的邻近方法论

- 不是"需求调研"——尽调是全面的家底摸底（含政治/系统），需求调研只聚焦问题
- 不是"销售拜访"——尽调服务于交付，不是为了成交
