# 规模化复制与产品化

## R — 原文 (Reading)

> "如果你不把现场学习转化为产品资产，你得到的只是一堆定制项目。……麦格鲁的表述是另一个角度：FDE 模式成立的标志，是『每个后续客户的定制量递减』——如果你做的定制工作不随客户数递减，你就不是在做 FDE，是做人天生意。"
>
> — 范冰《前线部署工程师》7.1

---

## I — 方法论骨架 (Interpretation)

规模化复制是 FDE 模式与咨询业、外包业之间的最后一道防线。三级复制杠杆：

1. **一级：知识复制（打法手册）**——把"怎么做"写成文档（模板/清单/培训材料），新人上手从一年压到三个月；多数团队止步于此
2. **二级：组件复制（工具与代码）**——连接器/评估框架/部署模板/行业数据模型；下一支团队起点是上一项目的肩膀
3. **三级：产品复制（平台能力）**——把反复出现的定制抽象为平台标准能力，从此该需求不再需要任何工程师到场；前两级降低交付成本，第三级消灭交付成本

配套机制：
- **失败复盘三机制**（失败是复制的原材料）：复盘无罪化（对事不对人）/ 教训结构化（进打法手册雷区章节+尽调清单）/ 失败适度外传（脱敏后对外分享=高效信任营销）
- **组织政治三心法**：扩张带着"当地人"（邀请部门地头蛇参与适配）/ 每步扩张有"受益者"（讲清楚各部门得到什么）/ 永远给"旧秩序"留体面（尊重旧流程维护者）
- **产品化四问**：个性还是共性（三客户独立出现=产品信号）/ 泛化代价小于收益（现场代码快而糙）/ 能否被不会写代码的人用（抽象层选对用户群扩大百倍）/ 收编后现场还有空间吗（收编太多现场退化为配置员，FDE 灵魂就死）
- **借势与传播**：定义议题（一手认知是议题定义权货币）/ 传播三圈层（从业者社区/客户行业社区/生态伙伴网络）/ 产品内置裂变因子（可见性设计/协作式准入/自助探索层/价值证据）

终极证据：毛利率逐年上升——ServiceNow 63.2%→79%、Workday 54.1%→76%、Palantir 79%→82%。开局都不好看，往后越跑越轻。

## A1 — 书中的应用 (Past Application)

### 案例1: Palantir Foundry 自下而上
- **问题**: 平台能力从哪来？
- **方法论的使用**: 核心组件诞生于苏黎世/休斯顿/圣保罗等客户现场——各地 FDE 为本地问题造的工具，经过数年自然选择与平台化收编长成统一产品
- **结论**: 2014 年产品战略"强烈的观点，松散地持有"，任凭现场百花齐放，活下来的收归核心
- **结果**: 年收入数十亿美元的平台

### 案例2: 毛利率三次回答
- **问题**: "派人下现场毛利怎么可能高？"
- **方法论的使用**: 平台切换期重仓实施与服务的公司，毛利率逐年爬升
- **结论**: 训练营让大量集成工作由客户侧完成，服务成本持续摊薄
- **结果**: Palantir 82% 毛利率比绝大多数"纯软件"公司还漂亮

### 案例3: 桑卡尔的赌注（借势+平台）
- **问题**: ChatGPT 出来后 Palantir 怎么办？
- **方法论的使用**: 判断模型会商品化、价值向两端聚集（算力芯片+本体语义层），把大半工程师压到 AIP 平台
- **结论**: 模型越强越便宜，"把模型接进现实"的那段工程就越值钱
- **结果**: 股价从个位数涨到 200 美元上下，美国商业收入连续多季度三位数增长

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 交付做多了，想规模化/产品化
2. 团队扩张但交付质量/效率不稳定
3. 失败项目多，想把教训变资产
4. 毛利率上不去，怀疑"是不是咨询公司"

### 语言信号

- "我们做了好多定制项目，怎么变成产品？"
- "团队扩到 50 人了，交付质量开始不稳"
- "怎么把失败项目变成组织资产？"
- "毛利率一直上不去怎么办？"

### 与相邻 skill 的区分

- 与 `delivery-automation`：自动化是效率杠杆（内部），规模化复制是组织能力+产品化（更宏观）
- 与 `trust-marketing`：借势/传播圈层是信任营销的获客侧，scale-copy 侧重组织复制能力

## E — 可执行步骤 (Execution)

1. **评估三级杠杆现状**
   - 完成标准：回答——打法手册建了吗（一级）？组件库有吗（二级）？哪些定制反复出现（三级信号）？
   - 判停条件：只有一级 → 识别到"多数团队止步于此"的陷阱，补二级
   - 备注：标志性检验——第 N 个客户的定制量比第 1 个显著小吗？

2. **建失败复盘机制**
   - 完成标准：复盘无罪化（对事不对人）+ 教训结构化（进手册雷区章节+尽调清单）+ 适度外传（脱敏）
   - 判停条件：复盘与绩效挂钩 → 人们开始修饰失败，机制报废

3. **用产品化四问筛平台候选**
   - 完成标准：对每个"反复出现的定制"过四问——三客户独立出现？泛化代价小于收益？能被非工程师用？收编后现场还有空间？
   - 判停条件：四问答不全 → 留在组件层，不强行平台化
   - 备注：平台里每个能力都是终身维护承诺

4. **处理扩张的组织政治**
   - 完成标准：扩张带当地人/每步有受益者/给旧秩序留体面
   - 判停条件：扩张引发部门反弹 → 政治心法没做，回炉

5. **盯毛利率曲线**
   - 完成标准：按月记录交付毛利率，观察是否随平台化上升
   - 判停条件：连续多个季度不升 → 回流机制失效，回 delivery-automation 检查
   - 参考：纯人力交付期 20-40%，平台复用度上来后向 60% 以上

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 单个客户交付执行（用 deployment-activation）
- 商业模式还没跑通时（先验证再复制——MVD/激活是前提）

### 书中警告的失败模式

- 抽掉复制内容 = 重新发明咨询公司（收入增长与人数线性）
- 掩盖失败：把金矿当垃圾埋掉
- 平台收编过度：现场退化为配置员，FDE 灵魂（现场创造力）死了
- 手册文档坟场：不嵌入流程等于不存在
- 无负责人手册：一年内腐烂成误导新人的陷阱

### 作者的盲点 / 时代局限

- Palantir 三级杠杆用 20 年+情报级客户才跑通，中小团队复制路径书中只给了 N 公司一个乐观样本
- "平台化"假设组织有平台团队；对多数小团队，产品化的四问可能长期答"不"，停留在二级杠杆是合理选择

### 容易混淆的邻近方法论

- 不是"咨询公司化"——咨询卖人天，FDE 规模化靠定制递减
- 不是"外包转产品"——是现场学习回流产品资产
