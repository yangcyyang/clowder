# 灯塔客户策略与排期

## R — 原文 (Reading)

> "灯塔客户——那种不仅能给你收入，更能给整个行业发信号的客户。灯塔的战略价值，在 FDE 模式下被成倍放大：第一，灯塔是最强的销售资产。企业客户决策链长、风险厌恶度高，同行背书是最短的说服路径。……第三，灯塔的质量比数量重要一个数量级。你的产能天然稀缺——一支精英团队同期能深度服务的客户是个位数，接错一个，代价不是『少赚一单』，是一支顶尖团队被泥潭占用半年。"
>
> — 范冰《前线部署工程师》3.1

---

## I — 方法论骨架 (Interpretation)

灯塔客户策略是 FDE 获客的核心：不追求客户数量，追求"发信号"的质量。三大战略价值：

1. **最强销售资产**——同行背书是最短说服路径（企业市场信任排序：厂商宣传 < 分析师报告 < 同行公开案例 < 同行私下推荐）
2. **决定产品基因**——前十个客户事实上参与塑造产品；选错灯塔，产品被带向没有普遍性的方向（a16z"聪明地卖"：选有共性的理想客户画像，让学习可累积）
3. **质量比数量重要一个数量级**——精英产能天然稀缺（一支小分队同期高质量交付不超过两个项目），接错一个 = 团队被泥潭占用半年

配套：
- **需求蝗虫识别**（三特征）：需求与战略方向明显偏离 / 把 FDE 当廉价外包使唤 / 内部政治消耗大
- **灯塔特有检验**：合作初期谈好"成功后愿不愿意站出来公开背书"；不愿公开的灯塔价值至少打对折
- **排期三原则**：按战略价值排不按合同金额排（决策矩阵：灯塔价值 × 学习价值，双高可倒贴优先）；把"等待"产品化（排队期给数据准备清单/组织预热/远程诊断）；永不承诺超越产能的并行
- **生态捆绑三类伙伴**：云厂商与大平台 / 咨询公司与系统集成商 / 客户的客户（预埋"可再交付性"）

## A1 — 书中的应用 (Past Application)

### 案例1: Harvey × 年利达
- **问题**: 法律 AI 怎么进入顶级律所市场？
- **方法论的使用**: 官宣第一个大客户年利达（3500 律师、43 办公室）——灯塔一亮，普华永道、佳利接踵而至
- **结论**: 法律行业最讲出身，拿下年利达等于拿到整个顶级律所市场的通行证
- **结果**: 2026 年用户超 10 万律师、1300 家组织，估值 110 亿美元

### 案例2: Palantir 中情局
- **问题**: 怎么打开商业市场？
- **方法论的使用**: 中情局是最严苛也最有背书价值的客户；情报界信任变成敲开华尔街、制造业、政府市场的钥匙
- **结论**: 灯塔的背书价值可跨市场转移
- **结果**: 二十年市值破 4000 亿美元

### 案例3: Barry 的排期矩阵
- **问题**: 为什么 Palantir 早期免费做试点？
- **方法论的使用**: 赌排期矩阵——灯塔价值和学习价值双高的客户，倒贴资源优先做
- **结论**: "错误的试点烧掉的不只是当下的成本，还有产品复利"
- **结果**: 教训沉淀为产品资产（Foundry 的起源）

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 多个潜在客户候选，需要排序先做哪个
2. 判断一个客户是不是"灯塔"（还是需求蝗虫）
3. 设计排期与产能分配（接几个、怎么并行）
4. 规划生态合作（云厂商/咨询/集成商）

### 语言信号

- "这两个客户先做哪个？"
- "这个客户合同很大但感觉不对劲，要不要接？"
- "我们产能不够，客户怎么排队？"
- "要不要和咨询公司合作？"

### 与相邻 skill 的区分

- 与 `poc-rejection`：拒绝机制防烂尾项目，灯塔策略选"对行业发信号的客户"（更偏正面筛选）
- 与 `trust-marketing`：灯塔策略制造背书素材，信任营销负责把这些素材传播出去

## E — 可执行步骤 (Execution)

1. **给候选客户打双维分**
   - 完成标准：每个候选评估——灯塔价值（行业信号强度 1-5）+ 学习价值（可沉淀复用能力 1-5）
   - 判停条件：双低的大合同 → 最危险，警惕（钱多但套牢团队）
   - 备注：双高客户可以也应该倒贴资源优先做

2. **识别需求蝗虫**
   - 完成标准：对照三特征排查——需求偏离战略？当廉价外包？内部政治消耗大？
   - 判停条件：三中二 → 说不（即使合同诱人）

3. **谈灯塔背书条件**
   - 完成标准：合作初期谈好——成功后愿不愿意联合发布案例/行业会议现身说法/接待潜在客户参访
   - 判停条件：明确拒绝公开背书 → 灯塔价值至少打对折，重新评估排序

4. **设计排期与等待期**
   - 完成标准：明确同期并行上限（参考：一支小分队 ≤ 2 个项目）；排队客户拿到"等待产品化"清单（数据准备/组织预热/远程诊断）
   - 判停条件：排期超过产能 → 宁可把"档期排到下季度"当稀缺性卖，也别多接

5. **规划生态捆绑**
   - 完成标准：识别可借力的伙伴类型（云厂商联合销售 / 咨询集成商结盟 / 客户的可再交付性），并为每一类写出具体动作
   - 判停条件：只想到"自己全干" → 浪费杠杆

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 存量客户续约管理（用 retention-defense）
- 消费级产品获客（用种子用户逻辑，无"灯塔背书"概念）

### 书中警告的失败模式

- 把产能当无限：接单超过产能，多项目并行损耗远大于想象
- 被需求蝗虫吸引：合同额诱人但吸干团队
- 灯塔不亮：不愿公开背书的灯塔价值打对折
- 选错灯塔：产品被带向没有普遍性的方向，学习互相抵消

### 作者的盲点 / 时代局限

- "精英团队同期 ≤ 2 个高质量项目"的假设在模板化/自动化成熟后开始松动（交付自动化降门槛）
- 生态捆绑（尤其咨询巨头）在 2026 年出现"借生态之名吃掉交付层"的新风险，需双向警惕

### 容易混淆的邻近方法论

- 不是"只做灯塔"——灯塔是获客策略，交付质量仍靠 MVD/激活
- 不是"人脉销售"——灯塔的背书价值来自交付结果，不是关系
