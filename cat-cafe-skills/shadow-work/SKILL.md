# 影子工作法：现场发现真痛点

## R — 原文 (Reading)

> "跟着真实用户，过完他真实的一天。不是采访他，是坐在他旁边看他工作——看他打开哪些系统、在哪些电子表格之间复制粘贴、在哪些环节皱眉头、绕过哪些『官方流程』。……重点观察『变通』，而不是『流程』。官方流程图告诉你组织『应该怎么运转』，变通告诉你组织『实际怎么运转』——每一个变通，都是一个未被满足的痛点在尖叫。"
>
> — 范冰《前线部署工程师》2.4

---

## I — 方法论骨架 (Interpretation)

影子工作法（Shadow Work）是 FDE 的需求发现核心方法。传统调研问"你要什么"，影子工作法看"你在做什么"。核心逻辑：

1. **痛不会出现在会议室，只会出现在工作现场**——士兵不知道"可以向软件要路边炸弹预警"，痛点用户自己说不出来
2. **看比问更真**——人对"哪里不对"的判断力远强于对"要什么"的想象力；只有行为不会撒谎
3. **重点观察变通而非流程**——每个变通（绕过的官方流程）都是一道组织的疤，疤下是系统失败，也是 FDE 的机会
4. **警惕翻译过的痛点**——信息部门把业务痛点翻成技术需求、采购翻成合规条目，每转一手失真一次；绕过翻译件，直达疼痛的神经末梢
5. **最高质量的调研发生在共同劳动中**——访谈里客户是"被研究对象"警惕而表演；并肩干活时松弛而真实

配套原则（行胜于言三层）：
- 客户不知道自己要什么（演示循环：问"哪里不对"而非"要什么"）
- 客户说的和做的是两回事（律师例：问卷说愿意用，实际用 ChatGPT）
- 共同劳动中真相最大密度涌现（调试间隙的"其实这个字段我们从来不信"）

## A1 — 书中的应用 (Past Application)

### 案例1: 伊拉克战场路边炸弹预警
- **问题**: 士兵需要什么工具？
- **方法论的使用**: 驻场工程师跟着巡逻队出任务，亲眼看到车队在可疑路段前的犹豫与恐惧
- **结论**: 士兵说不出来的需求（他们以为这就是巡逻生活的一部分）
- **结果**: 改变了战场的简陋地图工具

### 案例2: OpenAI × 约翰迪尔
- **问题**: 农民真正需要什么？
- **方法论的使用**: 飞到爱荷华跟着农艺专家和农场主下地，看施药决策、看哪些信息真正进入决策、看季节死线如何支配一切
- **结论**: "难的是找到那个没人写进文档的工作流、人们真正信任的那个数据源、以及知道流程为什么是那样的那个人"
- **结果**: 化学品使用减少最高 70%，农户互动频率提升 6 倍

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 进场第一周，需要找到客户真正的痛点（而非客户口头说的）
2. 客户/业务方描述的需求模糊或可疑，需要验证真伪
3. 需要摸清组织的隐性工作流、真实信任的数据源
4. 做需求调研时想超越问卷/访谈的局限

### 语言信号

- "客户说要个数据平台，但我感觉不是真需求"
- "进场第一周该干什么？"
- "怎么挖掘用户的真实痛点？"
- "做了问卷调研，结果感觉不太靠谱"

### 与相邻 skill 的区分

- 与 `psf-screening`：影子工作法是 PSF 痛点关的"取证手段"——PSF 判断值不值得，影子工作法找到痛点本体
- 与 `site-due-diligence`：影子工作法是尽调中"流程地图"和"组织地图"的观察方法

## E — 可执行步骤 (Execution)

1. **选人：跟着谁过一天？**
   - 完成标准：选"实际干这活的人"（不是经理/采购），且包含"知识枢纽"（所有人遇到问题都找他的人）
   - 判停条件：只约到会议室访谈 → 明确拒绝，坚持到工位旁

2. **观察记录四件事**
   - 完成标准：记录——打开哪些系统、在哪些表格间复制粘贴、在哪些环节皱眉头、绕过哪些官方流程
   - 判停条件：观察记录里没有"变通" → 观察还不够深，继续蹲
   - 重点：标注"变通清单"——每个变通 = 一个未被满足的痛点

3. **核对真伪：行为 vs 说辞**
   - 完成标准：把观察到的行为与访谈/问卷中的说法对照，标出"说的与做的不一致"处
   - 判停条件：所有说法都与行为一致 → 警惕，可能客户在表演（被研究对象心态）

4. **产出痛点清单并回访确认**
   - 完成标准：写出 3-5 个"具体的人 + 具体频率 + 具体痛点"条目，找业务方逐条确认
   - 判停条件：痛点写不出"具体的人" → 还没找到真痛点，回到步骤 1
   - 输出：痛点清单进入 PSF 三关检验

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 纯远程项目且无任何现场机会（远程可部分替代：看工单数据、看系统日志，但第一手认知必须物理创造）
- 问题已明确、只需技术实现时（过度调研是浪费）

### 书中警告的失败模式

- 把访谈当观察：客户是"被研究对象"时会防御
- 只问不跟：听"要什么"而不是看"做什么"
- 依赖翻译件：对信息部门/采购转述的需求负责，而不是对痛点负责
- 观察流程而非变通：看"应该怎么运转"而看不到"实际怎么运转"

### 作者的盲点 / 时代局限

- 影子工作法成本高（物理在场），2026 年 AI 自主访谈（特赞丁鑫栋做法）开始替代部分问卷场景，但"行为观察"仍难被替代
- 高价值观察点（变通）在高度数字化组织里变少，但暗数据（私藏表格）仍在

### 容易混淆的邻近方法论

- 不是"用户访谈"——访谈问"要什么"，影子工作法看"做什么"
- 不是"田野调查"的全部——只聚焦痛点发现，不做全面人种志
