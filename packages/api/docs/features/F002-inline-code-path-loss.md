# F002: 排查消息管道吞掉本地绝对路径

> Status: idea | Priority: P1（阻断交接） | Owner: TBD

## Why

2026-07-12 的同一 thread 中，Pi 汇报 GitHub stars 数据位置时，反引号与代码块中的路径先后显示为空；第三次改成纯文本后仍没有显示路径。随后墨墨汇报弹药库时，一条本地绝对路径在“产品项目/clowder”处截断。

因此问题已排除“仅反引号/Markdown 处理”的假设，升级为消息管道对某些本地绝对路径的过滤、转义或截断问题。它已实际阻断数据交接，临时以约定的仓库内固定路径绕过，不能再按单次笔误处理。

## What

以不含敏感文件的测试路径最小复现，逐段核对消息输入、发送前清洗、持久化、API 返回与前端渲染。定位对本地绝对路径的过滤、转义或截断点；修复后保证路径原样可见、可复制，不暴露无关内容。

## Acceptance Criteria

- [ ] AC-1：纯文本、行内反引号、fenced code block 三种形式的本地绝对路径均可发送、持久化并完整显示
- [ ] AC-2：定位并记录丢失发生在输入、发送前清洗、持久化、API 返回或前端渲染的哪一环
- [ ] AC-3：API 返回的原始消息内容与输入一致，前端渲染不吞字符
- [ ] AC-4：覆盖带空格路径、斜杠、下划线及多行代码块的自动化回归测试
- [ ] AC-5：修复后在实际 thread 手工发送一条无敏感数据的测试路径，并提供画面证据

## Open Questions

- 哪些绝对路径模式会触发过滤或截断，待最小复现确认。
