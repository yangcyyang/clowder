# Raft 第九轮研判：垃圾票根治方案（原料 OrbitOS-CN/00_收件箱/clowde0707/clowder0723/raft-第9轮.md）

## 事故回放（本方，2026-07-26 晚）

`task_claim --message-id`（抄自 Raft）被执行猫当"记账动作"每轮使用：拿同伴裁定、自己的换班回述去认领 → 消息自动转票、标题=原文 → 一晚 8+ 张垃圾票；gate 清完存量，自己的清理汇报又被转成新票。平台分类器自动建票早已全关——垃圾票全部来自这条路径。纯纪律（SOP 纪律 11）已被实证守不住。

## Raft 的三层防护（我们缺的）

1. **结构层【平台机制，我们缺的最关键一条】**：thread 内消息不可转票——"Only top-level channel / DM messages can become tasks. Messages inside threads are discussion context"。工作流的中间产物（裁定/回述/进度）物理上没有可 claim 的对象。
2. **语义层【纪律】**：claim = 开工前置仪式（一次性），不是记账；进度的指定去处是票的 thread。Raft 实测：多小时工作流全程 1-2 张票，agent 每轮绝不重新 claim；本人两周 message-id 认领仅 1 次。
3. **形态层**：健康的转票**全部来自人类消息**（292 张历史票实测）；agent 的工作票全部走显式 `task create` + 自拟标题。

Raft 也有的裸点（别学）：转票标题原文全文无截断（板上最长 754 字符）——没痛只因低频；明确建议我们**强制自拟短标题而非截断**（截断截出半句话、Clowder 侧真实带出过密钥）。

## 定稿：平台四规则（批次 4-B 追加 B5 节实施）

| # | 规则 | 来源 |
|---|---|---|
| B5.1 | **分支/讨论 thread 内的消息不可转票**；拒绝时给猫可读提示"讨论上下文不入票；新工作请 task_create + 自拟标题" | Raft 结构层规则照抄 |
| B5.2 | **猫发的消息一律不可经 message-id 转票**（人类消息可）；猫的工作要成票必须显式 task_create + 自拟标题——"直接消灭清理汇报被转成新票这种自噬" | Raft Q5 必配规则② + 292 票实测规律 |
| B5.3 | **同猫同 thread 已有活跃票 → 转票降级为挂进度**：消息作为进度事件挂到活跃票，发可见提示卡"已挂到 #N；若这是新工作请显式建票"（显式逃生门，防真新工作项被吞） | Raft Q5 选 a + 副作用缓解 |
| B5.4 | **message-id 转票强制随附自拟标题（≤60 字）**，原文进票 thread 首条不进标题；不提供标题 → 拒绝。mcp-server claim 工具 schema 同步 | Raft Q3 明确建议（反对截断） |

各带 env 开关默认开；红→绿测试；存量票不迁移（已由 gate 人工清）。

## 巡板操作规程（可照抄版，交 gate 猫执行，纪律层不进平台）

- **何时**：事件驱动——批次收官 gate 必巡 / 交付前后自巡名下票 / 被质疑专项巡；
- **每张非 done 票问三问**："下一步动作是什么？谁欠的？还成立吗？"——任一答不出=处置对象；
- **垃圾票三判定**（满足其一）：标题=对话碎片；无可验交付物；创建后 thread 零活动且无人追；
- **处置**：关闭优先且必须带证据评论（为什么关）；重复票评论指向 canonical 票再关；**从不删除**。

## 配套修正

- 派工提示词措辞（如推特日报 SOP 的"先认领任务"）：待 B5 上线后无需改——平台会把误用挡回并指路；
- SOP 纪律 11/12 保持（管人的部分）；本轮证明"纪律+平台防呆"缺一不可——"你们的实验已经证伪了纯纪律，一晚 8 张垃圾票就是数据"（Raft 原话）。
