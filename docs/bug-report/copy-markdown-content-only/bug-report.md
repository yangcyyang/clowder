# Copy Markdown 只复制消息正文

## Bug 诊断胶囊

| 栏位 | 内容 |
| --- | --- |
| **1. 现象** | 消息右键菜单的 `Copy Markdown` 会额外复制发送者、时间和引用符号；期望原样复制消息 Markdown 正文。 |
| **2. 证据** | 用户截图显示右键入口；`MessageActions` 调用 `buildMessageMarkdownQuote`，当前格式器显式拼接作者、时间，并给正文逐行加 `> `。 |
| **3. 根因** | 初始 Raft 对齐实现让单条右键动作复用了多选引用块格式器，与当前产品要求“复制正文”不一致；这不是剪贴板或 Markdown 渲染器造成的。 |
| **4. 诊断策略** | 逆向追踪右键菜单到剪贴板写入，并对照多选复制调用点；用组件测试锁定单条右键输出，同时避免扩大多选语义。 |
| **5. 超时策略** | 若最小测试无法复现，转查浏览器 Clipboard API mock 与消息 `content` 数据来源，不扩大到保存、分享或渲染链路。 |
| **6. 预警策略** | 若修改后仍出现元信息，说明存在第二个复制入口或运行时未加载当前构建；需重新执行运行时预检并从实际点击事件追踪。 |
| **7. 用户可见交互修正** | 单条右键 `Copy Markdown` 只输出界面可见的消息正文；Agent 内部运行时行不进入剪贴板，多选复制继续保留原有的来源分组格式。 |
| **8. 验收** | `message-actions-context-menu-raft.test.tsx` 覆盖单条正文原样复制；同时运行 `message-markdown.test.ts` 和 `message-selection-bar.test.tsx` 确认多选格式无回归。 |

## 报告人

用户于 2026-08-06 通过 Clowder 界面截图反馈。

## 修复方案

让单条右键处理器不再调用面向多选的引用块格式器。用户消息写入原始 `message.content`；Agent 消息写入界面同源的可见正文，避免复制被 UI 隐藏的内部模型或运行时行。多选入口保持不变，避免把本次单条交互修复扩展成另一项产品变更。

## 验证方式

先运行三条定向测试确认旧实现失败，再完成最小实现并重复定向测试、类型检查与相关质量门禁。
